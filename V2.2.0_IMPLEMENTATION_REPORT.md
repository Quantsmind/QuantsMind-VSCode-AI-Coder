## 9. Known failures and remaining gaps (explicit)

Not fixed (would mean editing either the manifest or the qualification test, both of which are pre-existing user work whose intent is not established).
2. **Karkain analysis is syntax-aware, not a full compiler**: no borrow/type checking, no diagnostics, no code generation; `import "C" { … }` blocks are skipped for the module graph; the `.kark` LSP/formatter in `Karkain-VSCode` is not reused or shipped here. Fixtures could not be validated by executing the real compiler (it cannot run on this machine).
3. **Architecture layer/role inference is heuristic for edge cases**: Karkain components report `unknown` layer (no reliable evidence → not guessed); Angular components are recognized by path/name, not by parsing `@Component` decorators; React/Vue relationships are import-level only.
4. **Go package fan-out**: `resolveGoReference` maps a package import to all files in the directory (pre-existing behavior), which produces many heuristic edges; the architecture view consumes them but caps output.
5. **`springframework`-only projects** (no `spring-boot`) are not flagged as Spring Boot; the Spring entry point was renamed specifically to `Spring Boot`.
6. **Monorepo is detected, not planned**: no per-package planning/workspaces; the webview shows it, analysis is workspace-wide.
7. **Environment**: Python is present but not on PATH by default; demos locate `Python311` on disk. `test:packaged` and any VS Code-dependent end-to-end UI runs were not re-run this session; VS Code network access in this machine is degraded (integration host reported unresponsive; registry fetch failed), though all suites completed.
