## 3. Findings — security and authorization (P0/P1)

### QM-GA-001 — P0 — MCP management UI launch-gate bypass
- **Component:** `src/commands/mcpManagement.ts` (`discoverTools`, `connectWithApproval`)
- **Type:** Security — authorization boundary
- **Evidence:** `discoverTools()` called `deps.manager.listTools()` with **no** workspace-trust
  check and **no** launch approval; `McpServerManager.listTools()` internally calls
  `connectApproved()`, which launches the server process. A user clicking
  "Query tools" on an unconfigured/untrusted server launched it without approval, defeating the
  launch gate enforced everywhere else (`mcpTools.ts` requires approval + trust; `connectWithApproval`
  does both).
- **Impact:** Unauthorized local process start from the management UI; trust boundary bypass.
- **Correction:** Extracted `ensureMcpLaunchApproved()` (trust check → modal approval →
  `grantLaunchApproval()`) shared by `connectWithApproval()` and `discoverTools()`; discovery now
  requires the same trust and approval as connect, and the modal text is accurate for both paths.
- **Regression:** Code re-inspection + compile; management UI is host-bound (no harness), tracked as
  QM-GA-033 (P3, deferred with reason). The shared helper is the single enforcement point.
- **Status:** CLOSED (fixed; verified by inspection and by the full unit suite; no UI harness added).

### QM-GA-003 — P1 — Cross-provider credential fallback for redaction
- **Component:** `src/chat/chatViewProvider.ts` (`currentSecret()`)
- **Type:** Security — credential isolation
- **Evidence:** On a scoped `secrets.forProvider(type).get()` failure, redaction silently fell back
  to the legacy `secrets.get()` — a *different provider's* credential would be used as a redaction
  candidate for outbound text for the active provider.
- **Impact:** Secret of the wrong provider could be forwarded in a way that corrupts redaction of the
  active provider's credential; violates least-privilege between credential scopes.
- **Correction:** On scoped read failure, log a warning and return `undefined` — never cross
  credential scopes.
- **Status:** CLOSED

### QM-GA-004 — P1 — Redaction read only the legacy key in the agent runtime
- **Component:** `src/agent/runtime.ts`
- **Type:** Security — credential hygiene
- **Evidence:** `secret` candidates for `CommandTools`, `runCommand` and the intelligence
  `retrieve()` path all read `secrets.get()` (legacy openai-compatible key only). A scoped provider
  key (e.g. Gemini) would be sent into logs and *not* redacted.
- **Correction:** Added `activeProviderSecret()` — scoped provider key first, legacy key as an
  explicit second choice, `undefined` on failure — and wired all three call sites through it.
- **Status:** CLOSED

### QM-GA-005 — P1 — Tool exceptions reached the model unredacted
- **Component:** `src/agent/codingAgent.ts` (`AgentToolRegistry.execute` outcome mapping)
- **Type:** Security — output handling
- **Evidence:** A thrown tool error was mapped directly into `AgentToolResult.error`, which is
  serialized into the tool-result message sent back to the model. A credential embedded in a tool
  exception would leave the process to the provider.
- **Correction:** `redactSecrets(outcome.error instanceof Error ? outcome.error.message : …).text`
  before surfacing.
- **Status:** CLOSED

### QM-GA-006 — P1 — JSON-RPC server error detail unredacted
- **Component:** `src/mcp/client.ts` (error frame handling)
- **Type:** Security — output handling
- **Evidence:** The MCP server's `error.message` was wrapped into `McpError('server', …)` verbatim;
  this string is logged and can flow into model-visible tool output.
- **Correction:** `redactSecrets(detail).text` applied at construction.
- **Status:** CLOSED

### QM-GA-007 — P1 — Command runner trust gate failed open
- **Component:** `src/commands/runner.ts` (`runApprovedCommand`)
- **Type:** Security — workspace trust
- **Evidence:** `if (options.trusted === false)` blocked; `trusted === undefined` executed. Every
  other boundary (`changeService`, `orchestrator`, `executionService` callers) treats trust as
  mandatory, and tests never exercised the missing-flag case.
- **Correction:** `if (options.trusted !== true)` refuses; production call sites already pass a
  boolean. Added regression test `refuses to run when workspace trust is not explicitly granted`.
- **Status:** CLOSED

### QM-GA-015 — P1 — Orchestrator trust gates failed open
- **Component:** `src/agent/orchestrator.ts` (`requireTrusted`, restore gate)
- **Type:** Security — workspace trust
- **Evidence:** `requireTrusted` used `(this.deps.isTrusted ?? (() => true))()`; the session-restore
  gate used `isTrusted === undefined || isTrusted()`. A caller forgetting the dependency silently
  gained full agent privileges.
- **Correction:** Fail-closed (`?? (() => false)`, `!== undefined && isTrusted()`). Restore and all
  start/approve/apply transitions now require an explicit trust grant.
- **Status:** CLOSED

### QM-GA-016 — P1 — Runtime trust default failed open (and the near-miss it exposed)
- **Component:** `src/agent/runtime.ts`, `src/extension.ts`, `test/integration/*`, `test/unit/workspaceRootPolicy.test.ts`
- **Type:** Security — workspace trust
- **Evidence:** `createAgentRuntime` defaulted `deps.isTrusted ?? (() => vscode.workspace.isTrusted)`.
  This engagement first changed the default to fail-closed — which was correct for defense-in-depth,
  but the **production wiring in `extension.ts` passed no `isTrusted`**, so the change alone would have
  disabled agent mode entirely in shipping builds. Caught by the integration suite
  (`chat webview integration — end to end`, timeout waiting for `awaiting-plan-approval`),
  root-caused, and fixed properly: `extension.ts` now injects
  `isTrusted: () => vscode.workspace.isTrusted` explicitly, keeping the fail-closed runtime default.
  Integration harnesses (`chat.test.ts`, `providerProfiles.test.ts`, `workspaceRootPolicy.test.ts`)
  were updated to inject the authoritative check rather than rely on defaults.
- **Impact:** Agent mode would have been unusable, or fail-open, depending on deployment.
- **Status:** CLOSED (fail-closed default; authoritative API injected at the two production/test entry points)

### QM-GA-017 — P2 — Central `isTrusted(undefined)` contract
- **Component:** `src/security/workspaceTrust.ts`
- **Type:** Documentation / design decision
- **Evidence:** `isTrusted(undefined) === true` is a documented, unit-tested contract ("services
  constructed outside the extension host keep their previous behaviour; every production call site
  supplies the authoritative check"). Flipping it in a GA pass would silently change documented
  behavior; instead every production call site now supplies an explicit check or receives the
  authoritative default.
- **Status:** ACCEPTED RISK / DOCUMENTED DESIGN — the fail-open hole at call sites was removed (see
  QM-GA-015/016); the helper now only serves hosts that supply no check, which in this extension is
  none. No production path depends on the fail-open branch.

### QM-GA-019 — P1 — Launch-approval fingerprint ignored environment
- **Component:** `src/mcp/serverManager.ts` (`fingerprint()`)
- **Type:** Security — approval cache integrity
- **Evidence:** Fingerprint covered command/args/url/auth/timeout only. Rotating `env` keys
  (e.g. swapping a token-forwarding variable to point at attacker-controlled logs) did not invalidate
  a cached launch approval — the approval carried over to a materially different process.
- **Correction:** `env` (sorted) is part of the fingerprint. Note: env **values** are included
  because approval semantics require the launch to be bit-identical to what was approved; env is
  process-local to the MCP server and never leaves the manager.
- **Status:** CLOSED

### QM-GA-021 — P1 — Approval⇄execution drift for commands
- **Component:** `src/agent/commandTools.ts` (`runCommand`), execution path
- **Type:** Security — exact-argument authorization
- **Evidence:** The modal showed `cwd` from a snapshot taken at entry; execution used a second
  snapshot taken after the modal closed. An allowlist edit or cwd change during the modal meant the
  executed command was not the authorized one (the runner would still refuse an unlisted command,
  but the *directory* and *allowlist* binding was not re-validated against what was shown).
- **Correction:** After the modal returns, the fresh snapshot's `cwd`/`workspaceRoot` must equal the
  values shown to the user and the command must re-validate against the *current* allowlist; any
  drift refuses with a distinct error. Execution uses the re-checked normalization.
- **Regression:** `commandToolsLive` suite green (15 tests) including the
  `narrowing the allowlist while the approval modal is open fails closed` case; new code path keeps
  the canonical `not in the configured validation allowlist` message.
- **Status:** CLOSED

## 4. Findings — reliability, correctness and accounting (P1)

### QM-GA-002 — P1 — Streamable HTTP timeout collapsed to NaN (circular import)
- **Component:** `src/mcp/transport.ts` (`httpTimeoutMs`, `raiseFetchError`), `src/mcp/client.ts`
- **Type:** Reliability — timeout enforcement
- **Evidence:** The transport referenced `DEFAULT_MCP_TIMEOUT_MS * 30` at **module scope**.
  `transport.ts` and `client.ts` import each other (error class / constant), so when `transport.js`
  loads first (via `client.js`), the constant is still `undefined` and the cap becomes `NaN`;
  `setTimeout(NaN)` fires essentially immediately, the fetch aborts, and every HTTP MCP call shows
  `The MCP server did not respond within NaNms`. Reproduced via `out/test/unit/mcpHttp.test.js` →
  `snapshots carry the transport and endpoint without leaking credentials`.
- **Correction:** Cap computed lazily (`maxHttpTimeoutMs()`), removing the load-order dependency.
- **Regression:** `mcpHttp.test.js --grep "snapshots carry"` passes (338 ms).
- **Status:** CLOSED — this defect was **introduced and fixed inside this engagement**; recorded as
  a newly discovered issue (§10, N2).

### QM-GA-008 — P1 — `truncated` lied about redaction
- **Component:** `src/commands/runner.ts`
- **Type:** Reliability — validation evidence integrity
- **Evidence:** `truncated: output.truncated || redacted.count > 0` — any redaction flip produced
  `truncated === true` even when output was orders of magnitude below the cap, making
  validation-evidence consumers trigger false "output clipped" handling.
- **Correction:** `truncated` reflects output clipping only.
- **Regression:** `caps output length` test still passes; no test asserted the old (incorrect)
  redaction coupling.
- **Status:** CLOSED

### QM-GA-009 — P1 — SSE parser corrupted data split on a CRLF boundary
- **Component:** `src/providers/sse.ts` (`parseServerSentEvents`)
- **Type:** Reliability — streaming protocol correctness
- **Evidence:** The buffer was normalized with `/\r\n/g → \n` **per chunk**, including any trailing
  lone `\r` at a chunk boundary. A CRLF split across chunks produced a phantom newline; multi-line
  `data:` payloads got a spurious blank line, terminating the event mid-payload → malformed JSON
  downstream, and (with retry) possible duplicate generation. Reproduced by unit test before fix.
- **Correction:** A trailing `\r` is held back until the next chunk (or end-of-stream) resolves it;
  normalization applies only to confirmed lines.
- **Regression:** New unit test `handles a CRLF pair split across chunks without phantom newlines`
  (plus full SSE suite).
- **Status:** CLOSED

### QM-GA-010 — P1 — Mid-stream retries were allowed (duplicate generation/billing)
- **Component:** `src/providers/openaiCompatible.ts`, `geminiCompatible.ts`
- **Type:** Reliability — duplicate side effects / cost
- **Evidence:** `streamStarted` was only set when the caller supplied `onDelta`. Non-streaming or
  silently-streamed completions that died mid-stream were treated as retryable at both layers;
  a provider re-send could duplicate an already-generated (billable) completion.
- **Correction:** All streamed deltas are tracked unconditionally; `withProviderRetry` forbids any
  retry once a delta has been emitted, at both provider sites.
- **Status:** CLOSED

### QM-GA-011 — P1 — Nested retry loops (up to 4 attempts vs documented 1)
- **Component:** `src/providers/completionService.ts`, `src/providers/openaiCompatible.ts`, `geminiCompatible.ts`
- **Type:** Reliability — retry semantics / cost
- **Evidence:** `completionService` wrapped `provider.complete` in `withProviderRetry` **and** each
  provider wrapped its `fetch` in another. Worst case 2 (outer) × 2 (inner) = 4 attempts,
  contradicting the documented single-retry policy and inflating paid-API cost.
- **Correction:** Outer loop removed; providers own the bounded retry (`MAX_COMPLETION_RETRIES = 1`),
  which already tracks its own stream state. Dead `AbortController` wiring in the completion service
  was removed as well (QM-GA-037).
- **Status:** CLOSED

### QM-GA-012 — P1 — Retry predicate disagreed with normalized error metadata
- **Component:** `src/providers/errors.ts` (`shouldRetryProviderError`, `normalizeThrownError`)
- **Type:** Reliability — retry semantics
- **Evidence:** `normalizeThrownError` marked `ETIMEDOUT`/`ESOCKETTIMEDOUT` as `retryable: true`, but
  `shouldRetryProviderError` computed eligibility from classification only, returning `false` —
  metadata and behavior disagreed in opposite directions.
- **Correction:** Reconciled to the documented contract of the codebase ("Timeouts are not retried
  automatically", enforced by `withProviderRetry`'s doc, the HTTP 408 mapping, and the unit-tested
  `shouldRetryProviderError ignores non-provider errors and explicit flags` case). The ETIMEDOUT
  branch was the outlier and now maps to a non-retryable `timeout`. The predicate still classifies;
  the surfaced metadata now agrees with the actual decision.
- **Status:** CLOSED

### QM-GA-013 — P1 — Failed mutating calls consumed change budgets
- **Component:** `src/agent/engine.ts` (tool dispatch)
- **Type:** Reliability — budget accounting
- **Evidence:** `filesChanged.add()` and `patchBytes +=` ran unconditionally after dispatch;
  a failed write consumed the changed-file and cumulative patch budgets, both blocking legitimate
  later work and misreporting the change set.
- **Correction:** Budget bytes and changed-file entries are charged only when the call succeeds.
- **Regression:** New test `a failed mutation charges no changed-file or patch-size budget`.
- **Status:** CLOSED

### QM-GA-014 — P1 — Cumulative patch budget charged at proposal, not at apply
- **Component:** `src/agent/orchestrator.ts` (`enforceChangeSetBudgets`, `approveChanges`, `approveRepair`)
- **Type:** Reliability — budget accounting
- **Evidence:** Cumulative bytes were added when a change set was **proposed**; a rejected or failed
  proposal consumed the budget forever, so repeated evaluation could permanently block legitimate
  work — and a proposal that never landed metered as applied.
- **Correction:** Budget check is now a pure check at proposal time; an **apply-time backstop**
  re-checks the exact set being applied against bytes *applied so far* (refusing deterministically
  before dispatch), and bytes are charged only for changes whose `applied` outcome is real.
- **Regression evidence:** B3 tests remain green (`v3GapClosure` cumulative-budget test,
  `executionBudgets`, `orchestratorLimits`) because the applied-then-repair chain is unchanged;
  partial applies charge only landed bytes.
- **Status:** CLOSED

### QM-GA-018 — P1 — Launch approvals wiped at capacity
- **Component:** `src/mcp/serverManager.ts` (`grantLaunchApproval` at capacity)
- **Type:** Reliability — approval cache integrity
- **Evidence:** `approvedLaunches.clear()` — forgetting N approvals for one unrelated server denied
  previously-launched servers. (Same defect class in `PaidConsent.granted.clear()`.)
- **Correction:** LRU eviction of the oldest tracked approval (insertion order), one at a time, in
  both stores. The caller's current approval is never wiped out from under them.
- **Status:** CLOSED (both sites; paid-consent recorded as QM-GA-041)

### QM-GA-020 — P1 — `mcp_list_tools` dropped schema information silently
- **Component:** `src/mcp/client.ts`, `src/mcp/mcpTools.ts`
- **Type:** Incomplete feature / UX honesty
- **Evidence:** Tools whose `inputSchema` exceeded `MAX_SCHEMA_CHARS` (32 KiB) were dropped **entirely**
  from discovery results with no warning to the model or the user; the model saw a toolset missing
  valid servers and could not form valid calls.
- **Correction:** The oversized schema is omitted but the **tool is kept** and flagged
  `schemaOmitted`; `mcp_list_tools` forwards size-bounded schemas for the rest, and emits
  `meta.warnings` naming the omitted tools. Tool description updated to state the contract.
- **Status:** CLOSED

### QM-GA-032 — P1 — Zero automated coverage for the path-containment boundary
- **Component:** `src/agent/pathSafety.ts`, `src/changes/fs.ts`
- **Type:** Test gap — security-critical boundary
- **Evidence:** No test exercised the resolver or `WorkspaceChangeFs`. Traversal, junctions to
  outside the root, and link-ancestor escapes were entirely unverified.
- **Correction:** New suite `test/unit/workspacePathSafety.test.ts` (10 tests): ordinary/normalized
  paths, explicit traversal, absolute/drive/colon-qualified/empty candidates, non-existent files,
  junction-to-outside root (refused), junction inside root (accepted), escaping link in the
  ancestor chain (refused). Linux CI covers the same paths via `fs` semantics that do not depend on
  win32 privileges; on this Windows host junction creation is used (no elevated privilege required).
- **Remaining:** `WorkspaceChangeFs` itself is `vscode`-bound; its containment core is shared logic
  exercised via `pathSafety`/`normalizeChangePath`. A host-level suite remains a follow-up
  (QM-GA-033/042-class gap, recorded).
- **Status:** CLOSED (boundary); residual host-bound coverage disclosed in §11.

## 5. Findings — moderate (P2)

### QM-GA-022 — P2 — Dedup guard was case-sensitive on win32
- **Component:** `src/execution/service.ts` (`run`)
- **Type:** Reliability — duplicate-run protection
- **Evidence:** Concurrent identical commands were deduplicated by exact cwd string comparison;
  `C:\repo` vs `c:\repo` (or separator drift) defeated it.
- **Correction:** `sameCwd()` — `path.resolve` + case-insensitive compare on win32.
- **Status:** CLOSED

### QM-GA-023 — P2 — Working-directory inspection misreported errors
- **Component:** `src/commands/runner.ts` (`inspectWorkingDirectory`)
- **Type:** Reliability / honesty
- **Evidence:** Any stat/realpath failure reported "does not exist", including permission-denied
  and I/O errors — an operator debugging EACCES would be told the folder vanished.
- **Correction:** ENOENT/ENOTDIR → "does not exist"; EACCES/EPERM → "inspected … permission denied";
  other errors → "could not be inspected"; root realpath failures reported distinctly.
- **Status:** CLOSED

### QM-GA-024 — P2 — Illegal engine transitions were coerced silently
- **Component:** `src/agent/engine.ts` (`transition`)
- **Type:** Reliability — diagnostics
- **Evidence:** An illegal state transition set `state = 'failed'` with no event — the session ended
  in a state no one could explain.
- **Correction:** An `error` event is emitted naming both states before the run is failed.
- **Status:** CLOSED

### QM-GA-025 — P2 — Undo reported failed restores as undone
- **Component:** `src/changes/apply.ts` (`UndoOutcome`), `changeService.ts`, `chatViewProvider.ts`, `changeTools.ts`, `extension.ts`
- **Type:** Reliability / data-integrity honesty
- **Evidence:** `UndoOutcome` counted only `restored` and `conflicts`; a restore that threw (I/O
  error, unsupported change, unknown path) landed in `results` but **nowhere in the counts**, so the
  history entry was marked `undone`, `undoable: false`, and both the UI and the tool output claimed
  success.
- **Correction:** `UndoOutcome` now carries `failed: number` (results with status `failed`);
  the history entry stays `partial` with `undoable: true` when anything is not restored; the chat
  notice and undo tool output name failures; the confirmation message includes the failure count.
- **Regression:** `test/unit/undoAccounting.test.ts` (4 tests covering failed/restored/conflict/mixed).
- **Status:** CLOSED

### QM-GA-026 — P2 — Change backups accumulated forever
- **Component:** `src/changes/changeService.ts` (`pruneBackups`), backup root layout
- **Type:** Reliability / security (unbounded plaintext before-images)
- **Evidence:** Every apply wrote a JSON before-image under `globalStorage/backups/<task>/<apply>/`.
  History is capped at `MAX_CHANGE_HISTORY`, but backups were never deleted — before-images
  accumulated without bound (disk exhaustion; sensitive file content outliving the task).
- **Correction:** After each successful apply, a best-effort sweep deletes backup directories whose
  `(task, apply)` is no longer in the capped history; containment is verified against the resolved
  backup root; any failure is logged and never affects the apply result.
- **Status:** CLOSED (implemented; automated test deferred — QM-GA-042)

### QM-GA-027 — P3 — `historyForTask` ordering contradicted `list()`
- **Component:** `src/execution/service.ts`
- **Type:** UX honesty
- **Evidence:** `list()` returns newest-first as documented; `historyForTask()` returned oldest-first.
- **Correction:** `historyForTask` returns newest-first; documented.
- **Status:** CLOSED

### QM-GA-028 — P2 — Hardcoded `User-Agent` version
- **Component:** `src/providers/modelDiscovery.ts`
- **Type:** Honesty / compatibility
- **Evidence:** `QuantsMind-VSCode-AI-Coder/1.0.0` — every request claimed a years-old version.
- **Correction:** Discovery now uses the shared `userAgent()` (version set from the manifest at
  activation).
- **Status:** CLOSED

### QM-GA-029 — P2 — Unhandled stdin stream errors could crash the host
- **Component:** `src/mcp/transport.ts` (`send`)
- **Type:** Reliability — process boundaries
- **Evidence:** `child.stdin?.write(...)` with no `error` handler; a server dying between approval
