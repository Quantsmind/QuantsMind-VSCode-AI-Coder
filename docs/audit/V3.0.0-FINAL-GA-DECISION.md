## 3. What this engagement changed and verified

### 3.1 Webview — duplicate UI generations eliminated (new finding QM-GA-063)
The chat webview emitted **two merged UI generations** into one DOM: 25 duplicate `id`
attributes across 46 unique ids (e.g. two copies of the provider selector row, hero screen,
task panel, plan card, `messages`, `empty`, `task-panel`, `plan-card`). Both copies rendered
together (invalid HTML, broken screen-reader tree, duplicate controls where JS bound the
first of each id). This is a genuine accessibility regression and violates "Accessible names
and descriptions".
**Fix:** `renderChatHtml` rewritten to a single canonical layout (46 unique ids, zero
duplicates), adding `role`/`aria-live`/`progressbar` semantics on task status, plan-tab
buttons with `tab`/`tablist`/`tabpanel` and `aria-selected`, decorative SVG `aria-hidden`,
and `<title>` on icons without visible text.
**Evidence:** unit 15/15 passing; `webviewHtml.test.ts` also asserts every script-referenced id exists; duplicate-id scan clean; compile exit 0.

### 3.2 MCP management UI gate — testable pure decision (closes QM-GA-033)
The launch gate (trust check → modal approval → grant) shared by `connectWithApproval` and
`discoverTools` was embedded in a host-bound function with no dedicated tests. Extracted
`decideMcpLaunchApproval` (pure, no `vscode` import): fail-closed on missing/throwing/untrusted
or non-exact-`true` trust; deny on modal cancel or prompt failure. Six unit tests cover every
branch including host-failure cases.
**Evidence:** `test/unit/mcpLaunchGate.test.ts` 6/6. The transport/handshake/crash/oversized/
timeout paths remain covered by the six existing MCP suites. The management UI itself remains
host-bound (honest; documented).

### 3.3 WorkspaceChangeFs — host-bound tests (closes host-bound half of QM-GA-042 residual)
`test/integration/workspaceChangeFs.test.ts` (6 tests): in-root write/read/move/delete/exists,
traversal refusal (`../escape.txt`), absolute-path refusal, backups round-trip, binary-content
read, directory-as-file read yields error not data. Verified under the pinned VS Code 1.95.0
extension host.

### 3.4 Multi-root silent selection — user-visible notice (closes QM-GA-035)
Multi-root folders are no longer silently ranked invisible to the user.
`activate()` logs the selected root and shows a one-time informational message naming the
selected folder and the selection rule. Per-folder trust/approvals remain unchanged.
`rootPolicy` unit tests still assert scoring/tie-breaking/call-site parity.

### 3.5 404-without-session — verified closed with evidence (closes QM-GA-036)
`test/unit/mcpHttp.test.ts` — “an expired session fails the call and reconnects with a fresh
session”: first call succeeds; after expiry the call fails with `closed` (explicit, honest);

### 3.6 Transient extension-host unresponsiveness — investigated (§5 of the GA instructions)

three runs incl. the record-time run). The warning fires during normal startup/fixture setup,

The single earlier 1-of-6 failure correlated with this message but did not reproduce; two
consecutive full runs before this investigation and two after were green (124/2/0 then
130/2/0 after new tests). **Assessment: environment-dependent harness timing, not a product
defect.** Canceled/harness-only; no code change made.

## 5. Security findings closure (accepted risks reweighed)

**QM-GA-034 (insecure localhost) — reweighed, stays ACCEPTED RISK with explicit rationale.**
- The extension never listens on any port; no remote machine can reach “the affected endpoint”
  through the extension.
- Plain HTTP is allowed **only** to literal loopback hosts (`localhost`, `127.0.0.1`, `[::1]`,
  `::1`) and only when the user-visible `quantsmind.provider.allowInsecureLocalhost` is `true`
  (default). Remote plain-HTTP always fails, regardless of the flag.
- Credentials are only sent to the configured base URL; no credential is transmitted to other
  local processes. Failure mode: a same-machine tenant could read loopback model
  request/response traffic (prompts + responses). That is the documented tradeoff of local
  Ollama/LM Studio UX, disclosed in settings markdown, warn-logged per request, and removable
  with the flag.
- Not suitable as unconditional GA *distribution* default without caller awareness? — The
  documented audience is developers/local-first users; the flag is one click away and the
  warning is logged. Risk accepted with full disclosure; owners may flip the default at
  publication if they wish. It is not a silent or unknown risk.

**QM-GA-043 (manifest `preview: true`) — stays, honestly.** Two integration tests pin it;
the build is unpublished; flipping it is a publication decision, not a code change. README now
states GA-qualified local candidate and no publication claim. It remains ACCEPTED RISK with
explicit rationale (publication-time owner decision). It does not imply any security gap.

**QM-GA-036 — closed as evidenced (no code change required).** Semantics: first post-expiry call
fails with `closed`; next call transparently re-initializes. Bounded: no unbounded retry, no
replay. Covered by `mcpHttp.test.ts` (fixture with real expiry).

**All remaining 4 DEFERRED dispositions are now: 2 fixed/closed (033, 035, 036 — that's 3) + QM-GA-040 (lint baseline) — recount:**

- QM-GA-035 → CLOSED
- QM-GA-036 → CLOSED
- QM-GA-040 → DEFERRED (maintenance debt only; not security, stability or data).

**Assessment:** environment-dependent harness/startup timing artifact, not a product defect. No
code change is warranted. If it reappears in CI, treat it as an environment flake and investigate
the harness (waitFor guards), not the product.
