## 3. Changes implemented

- **Planning validation** (`src/agent/planning.ts`): outcome categories; truncation rejected even when the partial text parses; inspection-plan parsing (findings required, `relevantFiles` validated, embedded tasks discarded with warning); system prompt documents both plan kinds.
- **Orchestrator** (`src/agent/orchestrator.ts`): passes `finishReason` into the parser; logs `agent plan validation failed category=… finishReason=… errors=…`; inspection plans produce findings/relevant-files events and an "Inspection (read-only) approval" request; approval of zero-task plans completes with a findings report and schedules nothing; `checkpoint()` refuses to persist without a validated plan (info-log instead of save attempt).
- **Completion report** (`src/agent/report.ts`): inspection plans add findings to the evidence section.
- **Models** (`src/agent/models.ts`): `DevelopmentPlan.kind` (`implementation`|`inspection`), `findings`, `relevantFiles` — all optional/additive.
- **Chat quality** (`src/chat/prompts.ts`, `src/languages/registry.ts`): rewritten base/mode prompts (facts vs assumptions, no unverified execution claims, no unexplained mid-method stops, completeness and complexity requirements, Java 21 guidance, whitespace-only history turns dropped).
- **Truncation/continuation** (`src/chat/protocol.ts`, `src/chat/chatViewProvider.ts`, `media/chat.js`, `media/chat.css`): user-initiated **Continue (token limit)** — capped at 3 continuations/response, merged into the same transcript message, system prompt rebuilt for the continuation call, bounded depth tracked both sides of the webview boundary, explicit `assistantContinuation` wire type, visible `truncated at token limit` state. Partial output always preserved. Logs: request started/provider-received/cancelled/failed with shared request id; MCP `clientInfo.version` now carries the real extension version (`src/mcp/client.ts`, `src/mcp/serverManager.ts`, `src/agent/runtime.ts`, `src/extension.ts`).
- **Context transparency** (`src/chat/session.ts`, `src/chat/chatViewProvider.ts`): released-history accounting (messages + chars); user notice when older context was dropped; restore-time drops surface in history warnings and the log.
- **UI** (`src/chat/webviewHtml.ts`, `media/chat.js`, `media/chat.css`, `src/chat/protocol.ts`): code-block Copy retained; **Copy response** on every assistant message; **Copy log** (last 50 redacted lines) with feedback; composer manual vertical resize (drag/keyboard/double-click reset, 58–320 px, window-height bounded); compact icon **Refresh** with aria-label, spinner busy state and completion notice; jump-to-latest; keyboard-focusable assistant messages; delete/clear confirmations wording-aligned with single-confirmation flow and explicit success toasts; `agent session` vs `conversation` clearly distinguished.
- **Webview message parsing** (`src/chat/protocol.ts`): strict whitelist extended for `continueAssistant` and `copyLog` (no open passthrough).
