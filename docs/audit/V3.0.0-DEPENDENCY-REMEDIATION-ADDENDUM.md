## 2. Dependabot remediation (GitHub alerts #2, #3, #4, #6)

### serialize-javascript (alerts #2 High · #3 Moderate · #4 Low)

- Chain: `mocha → serialize-javascript ^6.0.2` (the only path; both root and nested
  mocha instances — `@vscode/test-cli → mocha@11.8.0 → serialize-javascript@6.0.2`).
- Fix applied (all three alerts, one dependency chain):
  - mocha upgraded `11.8.0 → ^12.0.3` (devDependency; engines.node `^20.19.0 || >=22.12.0`,
    satisfied by the Node 20/22/24 matrix).
  - npm override `serialize-javascript → ^7.1.4` (registry latest 7.1.4) — also covers the
    nested mocha under `@vscode/test-cli`.
  - Exact-copy verification after install: every copy in the tree resolves to **7.1.4**.

### minimatch (alert #6 Moderate — globparts-amplification DoS)

- Affected copies at intake: `10.2.6` ×7 nested under `@eslint/config-array`,
  `@typescript-eslint/typescript-estree`, `@vscode/test-cli`, `@vscode/vsce`, `eslint`,
  `glob`, `test-exclude`; plus `mocha → glob → minimatch@9.0.9` (nested). The task-target
  is `>=11.0.1` — no 10.2.x patch exists on the registry (10.2.6 is the last 10.x release),
  so parent ranges must not be trusted.
- npm **overrides** pin `minimatch → 11.0.8` (latest 11.x; last 11.0.x release at time of
  writing), applied to all nested copies.
- Direct dependency re-pinned to exact `11.0.8` to keep `verify:deps` (which requires an
  exact pin for the shipped runtime dependency) green.
