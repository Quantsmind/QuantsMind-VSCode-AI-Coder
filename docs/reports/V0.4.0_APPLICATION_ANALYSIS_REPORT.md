## 1. What the product is

A single-publisher VS Code extension (`quantsmind.quantsmind-vscode-ai-coder`, MIT) that turns the
editor into a chat-and-agent coding surface over an **OpenAI-compatible HTTP API**. It has no
bundled model and no vendor account: the user supplies a base URL, a model name and (for remote
hosts) an API key.

## 3. Provider layer — PASS

- **Contract over implementation.** `providers/types.ts` defines the `AiProvider` surface;
  `providers/registry.ts` is the single extension point and only registers
  `openai-compatible`. Adding a vendor means one registration, not touching the chat layer.
- **Transport choice is validated, not trusted.** `providers/endpoint.ts` rejects non-http(s)
  schemes, embedded credentials, query strings and fragments; plain HTTP is loopback-only.
- **Errors are normalised.** `providers/errors.ts` maps transport/HTTP/parse failures to a
  `ProviderError` with a stable `code` and a `retryable` flag; response bodies are never echoed raw.
- **Streaming is optional and bounded.** SSE parsing lives in `providers/sse.ts`; the adapter
  falls back to a buffered response when `stream` is false; `requestTimeoutMs` caps both.
- **Status is computed, not guessed.** `CompletionService.getStatus()` returns provider, model,
  endpoint host, credential presence/requirement and `ready`, which drives the status bar, the chat
  header and the "blocks sending before any request when the provider is not ready" test.
- **Insecure transport is now visible** — committed in `19fc16b`: one warn line per request that
  actually resolves to `http:`, naming host and setting only.

## 4. Chat, conversations and the webview — PASS

- **Typed protocol.** `chat/protocol.ts` defines **63 distinct message types** across host→webview and
  webview→host, with a length/format gate on every inbound message.
- **Persistence is versioned.** `chat/persistence.ts` stores conversations under
  `quantsmind.chat.conversations.v1` (schema v2) plus an active-conversation pointer; unreadable
  records are salvaged to `…unreadable.v1` rather than dropped; `mostRecent(exceptId)` never offers
  an empty conversation; `delete()` promotes a record that has messages (fixed in `fcc8a5a`).
- **Attachments are content-addressed.** `chat/attachmentContext.ts` stores path, content, char
  count, SHA-256, language id, selection flag, redactions and capture time; a stale file is
  re-read or flagged on restore, and the integration suite proves the "no longer matches the file on
  disk" path.
- **Webview is locked down.** Nonce-based CSP, no remote assets, no inline handlers; the HTML
  builder is unit-tested. UI assets: `media/chat.js` 66,860 B, `media/chat.css` 27,790 B,
  `media/icon.svg` 366 B.
- **Concurrency is explicit.** Sending sets `busy`; switching, clearing and deleting are refused
  while busy — a deliberate refusal, now pinned by a deterministic test (`f728c95`).

## 5. Agent workflow — PASS at code level, BLOCKED live

- **19 explicit states** (`idle … cancelled`) with a declared transition table; terminal states
  cannot be entered from arbitrary predecessors, and a failed validation goes to `diagnosing`,
  never `completed`.
- **Four approval kinds**: plan, change set, repair, validation command. Approvals carry a request
  id, are stored on the session, are invalidated before execution continues, and a stale id is
  refused rather than replayed.
- **One task owns execution.** The scheduler returns `waiting` while a task is running, awaiting
  approval, applied, validation-failed or repairing.
- **Bounded autonomy:** `agent.maxSteps` (6), `agent.maxRepairIterations` (1),
  `agent.timeoutMs` (180 s).
- **Session persistence** covers resume, focus, delete and completion reports;
  `sessions/` handles repository shape and migration.

Live agent behaviour requires the user's UI session; it is **BLOCKED** for this report and covered by
the Phase 7 protocol.

## 6. Change model, apply and undo — PASS at code level

- Per-file change records carry kind (`create`/`update`/`delete`), original and proposed content,
  and a baseline hash; review produces a diff without touching disk.
- Apply is gated on explicit per-file selection; zero selected files rejects; path containment is
  enforced; the baseline hash is compared before writing; the write is the only operation that sets
  `applied`.
- Undo restores from backups under `globalStorage`, leaves files modified after apply untouched, and
  reports conflicts. `changeHistory` persists the record so undo survives a reload.
- Unit coverage is split by concern: model, diff, apply, review, history, plan (`change*.test.ts`).

## 7. Command execution — PASS at code level

- Exact allowlist (default: `npm run compile`, `npm run lint`, `npm test`,
  `npm run test:unit`, `npm run verify`), application-scoped so a workspace cannot widen it.
- Independent destructive-command classification: a destructive command is refused **even when
  allowlisted** (`src/commands/policy.ts:135`).
- No shell: bare executable, no metacharacters, sanitized environment, timeout and output caps
  (`commands.timeoutMs` 120 s, `commands.maxOutputChars` 120,000).
- The model can never invoke the runner directly — only a typed user message does.

## 8. Workspace intelligence and context — PASS

- Index skips secrets, dependency folders, build output, binaries, empty and oversized files, then
  applies `.gitignore` plus user `excludeGlobs` with correct negation/anchoring semantics
  (`workspace/ignore.ts`, 7 unit tests in the ignore suite).
- Ranking is deterministic and testable: file-name matches beat path-only matches, entry points get
  a bonus, oversized files are penalised, tests are rewarded only when requested, and the result is
  hard-capped (8 files / 40,000 chars by default).
- Nothing is uploaded implicitly: context is attached explicitly, and prompt text is assembled from
  the allowlisted context only.

## 9. Security posture — mostly PASS, three recorded decisions

**Controls that are measured, not asserted:**

| Control | Evidence |
| --- | --- |
| Credential storage | `SecretStorage` only; `verify:vsix` fails the build if any contributed key matches `/api.?key|password|client.?secret/i` |
| Log redaction | 20 rules in `security/redact.ts` (128 lines) applied inside `Logger.write` to **every** line; covers `sk-`, GitHub/Slack/Google/AWS tokens, JWTs, `Bearer`, `Authorization`, `x-api-key`, URL userinfo, masked fragments and PEM blocks |
| Request-lifecycle proof | Integration test scans the whole Output channel of a real mock request for five credential shapes and the prompt text; 36/36 passing |
| Webview isolation | Nonce CSP, no remote assets, strict message protocol |
| Approval integrity | Request-id binding, no replay, separate plan/change/repair gates |
| Process safety | Exact allowlist + destructive classification + no shell + sanitised env |
| Data egress | No telemetry, no crash reporting, no updater; the only outbound call is the provider request |
| Trust gates | 8 `isTrusted` references across 5 files gating agent sessions, apply/undo and validation |

**Open decisions (from the Phase 5 audit, unchanged):**

- **F1 — Restricted Mode still allows workspace reads.** `src/context` and `src/workspace` contain no
  trust checks, so in an untrusted workspace chat can read files and include them in an outbound
  request. `untrustedWorkspaces.supported: true` therefore does not mean "nothing leaves the
  machine". Documented honestly in the README; the decision is gate the reads or state the exception.
- **F2 — `normalizeBaseUrl` fails open when the options argument is omitted.**
  `src/providers/endpoint.ts` defaults to `{ allowInsecureLocalhost: true }`. All four production
  call sites pass the resolved setting explicitly, so nothing is exposed today; the default is a
  latent trap.
- **F3 — `allowInsecureLocalhost` ships `true`.** Accepted and documented as default-on; mitigated
  by the new warn line. Whether to flip the default is a product decision.
