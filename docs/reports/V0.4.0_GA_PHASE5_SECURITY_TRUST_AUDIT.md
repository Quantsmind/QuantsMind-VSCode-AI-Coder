## 2. Credential absence in logs — PASS

Existing coverage asserted only that a specific fixture key did not appear
(`expect(sink.text).to.not.contain(TEST_KEY)`, streaming and error paths). A named-string check
cannot catch a differently shaped echo — a masked `sk-abc***wxyz`, an echoed `Authorization:` header,
or a `apiKey=` pair.

Added: `logs only sanitized shapes across a full request lifecycle`
([test/integration/chat.test.ts:377](../../test/integration/chat.test.ts#L377)) which drives a real
mock-provider request through the webview provider and then asserts over the whole captured Output
channel that none of `/sk-[A-Za-z0-9_-]{8,}/`, `/Bearer\s+\S+/`, `/authorization\s*[:=]/i`,
`/api[_-]?key\s*[:=]/i` occurs, that the prompt text itself is absent, and that both
`request context …` and `completion success …` were emitted. It passes; the integration suite is
**36 passing, 0 failing**.

The lifecycle lines themselves are shape-safe by construction — they carry identifiers, counts and
sizes only:

- `request context id=… provider=… model=… mode=… stream=… <breakdown> capturedAttachments=… capturedChars=… dropped=…`
  ([src/chat/chatViewProvider.ts:1826](../../src/chat/chatViewProvider.ts#L1826))
- `completion start provider=… model=… messages=… chars=… systemChars=… messageChars=… stream=… timeoutMs=…`
  and `completion success durationMs=… chars=… finishReason=…`
  ([src/providers/completionService.ts:107](../../src/providers/completionService.ts#L107),
  [:122](../../src/providers/completionService.ts#L122))
- `completion failed code=… status=… retryable=… durationMs=…` — the error object is passed as the
  second argument, so the message text is not concatenated into the line
  ([src/providers/completionService.ts:130](../../src/providers/completionService.ts#L130))

Redaction is applied before logging at the provider boundary
([src/security/redact.ts](../../src/security/redact.ts), 127 lines, **20 rules** — including
partially-masked provider echoes, `Bearer` forms, `x-api-key`, JWTs, URL userinfo, and PEM private
key blocks).

## 3. Credentials never reach settings — PASS

`verify:vsix` fails the build if any contributed configuration key matches
`/api.?key|password|client.?secret/i`
([scripts/verify-vsix.mjs:157-162](../../scripts/verify-vsix.mjs#L157)), and the packaged secret scan
rejects fixture keys and private-key material in every packaged text file
([scripts/verify-vsix.mjs:164-186](../../scripts/verify-vsix.mjs#L164)). The API key lives only in
`SecretStorage` (`API_KEY_SECRET_KEY`, [src/extension.ts:15](../../src/extension.ts#L15)). This audit
did not read or probe SecretStorage contents — host policy blocks that and the restriction was
respected; credential survival across upgrades is evidenced by the user's live provider call.

## 5. Findings raised as decisions (not fixed in this audit)

**F1 — Restricted Mode still reads and transmits workspace file content. Severity: medium.**
The context and indexing layers contain **zero** trust references (verified over
`src/context`, `src/workspace`, `src/chat/attachmentContext.ts`), while
[src/context/contextService.ts:78](../../src/context/contextService.ts#L78) reads file bytes straight
from disk and the chat send path calls it via `readUris`
([src/chat/chatViewProvider.ts:1358](../../src/chat/chatViewProvider.ts#L1358)). The manifest
declares `capabilities.untrustedWorkspaces.supported: true`.
So in an untrusted folder, opening a folder still permits its contents to be attached to an outbound
provider request. That is a real choice, not obviously wrong — VS Code permits read-only
contributions in Restricted Mode — but it must be *stated*, because "supported: true" reads as
"nothing leaves the machine" to a security reviewer.
Options: (a) gate context/indexing/attachment reads behind trust; (b) keep the behaviour and
document it in `APPROVAL_AND_SECURITY.md`, `LIMITATIONS.md` and the README's trust paragraph.
Recommendation: (a) for GA-public, (b) minimum for controlled distribution.

**F2 — `normalizeBaseUrl` fails open when the caller omits options. Severity: low (latent).**
[src/providers/endpoint.ts:23](../../src/providers/endpoint.ts#L23) defaults to
`{ allowInsecureLocalhost: true }`. All four production call sites pass the resolved setting
explicitly ([src/providers/completionService.ts:40](../../src/providers/completionService.ts#L40),
[:73](../../src/providers/completionService.ts#L73),
[src/providers/openaiCompatible.ts:64](../../src/providers/openaiCompatible.ts#L64),
[:108](../../src/providers/openaiCompatible.ts#L108)), so shipped behaviour is correct today. The
risk is the next caller that forgets the argument and silently gains plain-HTTP. Recommendation: make
the option required (or default `false`) and update the three unit tests that rely on the permissive
default. Deliberately left unfixed: it is shipped-behaviour-adjacent and outside the Phase 3
authorization.

**F3 — `allowInsecureLocalhost` defaults to ON, and an earlier project note claimed it was off.**
[package.json:306-310](../../package.json#L306) sets `"default": true` and
[src/config/defaults.ts:10](../../src/config/defaults.ts#L10) sets
`DEFAULT_ALLOW_INSECURE_LOCALHOST = true`. Plain HTTP to *remote* hosts is always rejected; the
setting only governs loopback. The GA roadmap draft said "default-off confirmed" — **that was wrong
and is corrected here.** Keeping the default is the sensible product choice (Ollama, LM Studio,
llama.cpp out of the box); flipping it is the conservative security choice. Either way GA needs the
description to state that a loopback endpoint receives the prompt in clear text on the local machine.

## 6. Dependency surface — PASS with triage

`npm audit --audit-level=high`: **19 findings — 1 low, 17 moderate, 1 high, 0 critical.**
The single high finding is `serialize-javascript@6.0.2`, reached only through `mocha` (verified with
`npm ls serialize-javascript`), i.e. the test runner — it is not in the dependency graph the extension
loads, and it cannot be in the VSIX because the packaged `node_modules` is asserted to contain
exactly one runtime package, `minimatch`
([scripts/verify-vsix.mjs:124-156](../../scripts/verify-vsix.mjs#L124)). CI now reports the audit on
every run without blocking it. **Residual gap:** the 17 moderate findings have not been individually
triaged in writing; that remains open for the sign-off document.

## 7. Egress surface — PASS

No telemetry, no analytics, no crash reporting: a source scan for `telemetry`, `analytics` and
`track(` returns nothing, and there is no outbound call outside the provider layer. The only network
egress is the configured provider endpoint. No localization layer exists either, so no strings are
fetched remotely.
