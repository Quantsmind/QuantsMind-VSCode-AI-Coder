## 4. Defect closed

`V0.3.4_HISTORY_RESTORE_DEFECT_INVESTIGATION.md` concluded **ROOT CAUSE CONFIRMED**: a persisted empty
`New chat` record — created by New Chat, always newest by `updatedAt`, and rendered in the dropdown
indistinguishably from the `New chat` action row — was what the new Restore command resolved to via
`mostRecent(except active)`. Fixed on both sides (empty records skipped by `mostRecent()` and by the
presentation filter; Restore driven by the selected conversation id; empty saves no longer re-stamp
`updatedAt`), verified by automation, installed, and **manually confirmed resolved** by M1/M2.
Status: **RESOLVED**.

## 6. Known behavioural notes (expected, not defects)

- The stored active conversation is still the blank New-Chat record from before the fix; the fix hides
  it from the history list rather than deleting it. Nothing was migrated or removed from user storage —
  by design, since deleting user data was out of scope.
- The two pre-0.3.4 conversations have no captured attachment context, so restoring them legitimately
  reports `legacy`/`unavailable` attachment chips and `capturedContextTurns=0`.
- VS Code garbage-collects superseded extension folders on next start; rollback depends on the backup
  copies, which are verified present.
